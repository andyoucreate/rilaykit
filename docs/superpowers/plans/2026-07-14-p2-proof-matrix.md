## Known gap found by this gate

| Gap | Pinned by |
|---|---|
| **A JSON-authored flow cannot carry initial values.** `compileForm` returns defaults out of band (`{ formConfig, defaultValues }`) because `FormConfiguration` has no defaults slot — the consumer forwards them via `<Form defaults>`. `compileFlow` returns a bare `WorkflowConfig`, which has no defaults slot *and* no out-of-band channel, so a step form's `defaultValues` block **and** its per-field inline `default` (the P2 streaming-friendly feature, T2) are both silently dropped. The consumer must hand-write the step-namespaced `<Flow defaults={{ stepId: { field: value } }}>` that the JSON already described. Not a regression: T5 specified `compileFlow → WorkflowConfig`, so the hole is by construction. Closing it is additive but crosses into the P1-frozen workflow engine (a `defaultValues` slot on `WorkflowConfig`/`StepDefinition` + seeding in `WorkflowProvider`), so it is left as a phase-boundary decision rather than taken unilaterally at the gate. | `tests/e2e/proof/compile-flow.proof.e2e.test.tsx: drops a step form’s JSON defaults — WorkflowConfig has no defaults slot (known gap)` — pins the CURRENT contract exactly (the JSON says `Acme`, the live step renders `''`, and `<Flow defaults>` is the only recourse). The day the slot lands, this test fails and must be rewritten into the positive assertion |
